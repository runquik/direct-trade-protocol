# Synthetic identity-control contract, draft 1

Root implementation decision following independent architecture review and the user's recovery approval. This is a library contract pending host integration and independent review, not Passport login or a production identity service.

- Identity genesis uses the permanent `DTP-PERSON-GENESIS-1` signing domain, independent of software release number, email, employer and host address. The full genesis digest is retained; its first 128 bits form the existing UUID-compatible entity identifier. Registration must compare the full genesis digest on any identifier collision rather than merge records.
- Genesis declares separate operational and recovery key sets; every initial key proves possession. Operational and recovery keys are disjoint, each with a threshold. The identity is self-certifying control, not a verified legal person.
- Normal rotation requires the old operational quorum and possession of all added operational keys. It cannot change recovery keys. Recovery uses the current recovery quorum to replace operational keys. Recovery-policy changes require the old recovery quorum, not ordinary credentials. Retired keys cannot be reinstated.
- Control transitions bind the exact prior digest and next sequence. The resolver must serialize acceptance using compare-and-set in durable storage. Pure helpers do not provide that transaction by themselves.
- The `resolver` supplied to `createIdentity` is configuration, not signed enrollment. The same genesis can derive the same identity at different resolver addresses; it does not authorize those resolvers. Before host acceptance the owner must sign a separate resolver enrollment, and the verifier must pin that binding. Replaying genesis at another resolver must not replace a verifier's enrollment.
- A current-head proof is a maximum 30-second authorization lease bound to an enrolled resolver key, identity, head, audience, unpredictable verifier challenge, issuance and expiry. Issuing proofs updates durable maximum lease expiry. Verifiers consume challenges once within their execution transaction and retain rollback checkpoints.
- A fresh higher-sequence head is a statement by the explicitly trusted pinned resolver, not an independently verified transition chain from the verifier's last digest. Same-sequence conflicting heads and rollback are rejected. Resolver equivocation is outside this helper's guarantee; a stored signed transition history and independent audit are separate requirements.
- A transition stops old-head proof issuance immediately. New control becomes effective after outstanding leases plus a five-second trusted clock margin. Resolution during that barrier fails closed. Existing leases remain potentially usable before that barrier; no instantaneous distributed revocation is promised. Hosts must reject expired leases at execution, not merely at request parsing.
- The pilot assumes clocks within the stated margin; broken clocks and resolver compromise are outside its guarantee. The margin is a documented compromise window, not an identity attribute supplied by an untrusted caller.
- Resolver replacement requires the existing resolver's freeze/transfer receipt and the destination's readiness, with old leases drained and epoch continuity. It is a separate required integration gate. A destroyed resolver cannot be replaced safely by silently promoting recovery keys at a new host; recovery from all infrastructure loss is not implemented by these helpers.
- Old v0.4 signed identities remain old identities. No automatic alias from identical email/name/key and no destructive reseed is permitted. An explicit provenance-preserving import remains a separate work item.

`identity-registry.ts` now provides an indexed database adapter with per-identity row locking, owner-signed initial enrollment (operational and recovery quorums), persisted lease expiry and transactional signed transition history. It refuses a conflicting enrollment, a foreign resolver configuration and frozen rows. Its PGlite tests exercise rollback and adapter recreation; this is not real PostgreSQL contention or full process/disk recovery evidence. No public route or directory has been enabled.

The registry now stores a minimal accepted-transition acknowledgment in the same history transaction. An exact previously accepted signed-envelope retry returns that historical acknowledgment without another write or new key state, including after its original submission window expires. A changed envelope cannot reuse it. This is not a fresh current-controller proof; active resolver binding is still required. This retry addition is pending independent recheck.

Required integration work still open: host command authentication and cross-host proof consumption, cooperative resolver transfer, explicit old-identity migration, service-principal sponsorship, a reviewed custody adapter and production recovery UX. A green helper or database-adapter test does not close F1.
