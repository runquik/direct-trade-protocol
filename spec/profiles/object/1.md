# `dtp/object@1`

Status: **registered** in [`spec/profiles/index.json`](../index.json) on October 22, 2026, after a second, separately coded implementation (`sdk/tests/interop/object-reader.ts`) passed the fixtures. Step 1 of the [verb-layer build order](../../../docs/foundation/verb-layer-proposal.md) (decisions V4 to V6, V18). A host admits the exact contract in [`1/profile.json`](1/profile.json) (publisher `dtp`, semantics `object-v1`) with `profile.admit`.

## Name and version

Kind `dtp/object@1`; profile `dtp.object/1`; contract version `1.0.0`. Minor versions within the major MUST be additive.

## Nature

A **state** kind: the minimal defining component of a discrete object that has no other defining kind, such as a location, an account, a vehicle, a sensor or a position in an organization. A product's defining component is `dtp/product@1` and a party's is `dtp/party@1`; they are not also objects of this kind.

The kind carries two verbs. **`create`** is its genesis, and means "entered the ledger", not "came into existence". **`retire`** is a revision to `retired` with a reason. Nothing is deleted. A sale is never a retirement: it is a transfer, carried by a later kind.

## Identity

- The object is the record `root_id`, the writer's id at genesis; its revisions are `record_id`s. Other companies reference it as `{minted_by, root}` and never write under its root ([object references](../verbs.md#object-references)).
- External identifiers (an SSCC, a VIN, an asset tag, a GLN) are how people and scanners recognize the object; they are not its identity.

## Payload

Schema in the bounded `dtp.schema/1` dialect with `nullable`, in [`1/profile.json`](1/profile.json):

| Field | Meaning |
|---|---|
| `class` | `<namespace>/<name>`: a protocol class listed in [`../classes.json`](../classes.json), or a class namespaced by an organization id. |
| `label` | A human name, or null. |
| `identifiers` | 0 to 16 distinct `{scheme, value}`, the scheme a dotted lower-case namespace. `gs1.sscc` (eighteen digits), `gs1.gtin` and `gs1.gln` are check-digit validated; any other scheme is opaque. |
| `status` | `active` or `retired`. |
| `retired` | Null while active; `{reason, note}` when retired, `reason` one of `scrapped`, `lost`, `consumed`, `ended`, `other`, and a note required for `other`. |
| `evidence` | 0 to 16 distinct [object references](../verbs.md#object-references) supporting the current status, such as the observation that found a lost object. |

## Semantics (`object-v1`)

1. The body passes every rule in the payload table (`validateObject`).
2. **Genesis** is born `active` (`checkObjectGenesis`).
3. **Revisions** (`checkObjectContinuity`): the class never changes; identifiers may be added and never removed. A retired object changes only by being found: its next revision is `active`, keeps its label, and cites at least one piece of evidence it did not cite before. An active object may be relabelled, gain identifiers or evidence, and be retired.
4. **One spelling per object** (`checkObjectOwner`): no evidence reference names the writing organization as minter.
5. A refused write is `invalid_object`; snapshot import re-checks rules 1 to 4.

## Relations

- [Verb-layer datatypes](../verbs.md): object references and classes.
- `dtp/product@1` and `dtp/party@1` are the defining components of products and parties; this kind is for everything else.
- `dtp/inventory@2` locations are still free strings; the flow ledger (build step 2) makes them references to `dtp/location` objects.

Regenerate with `node sdk/scripts/build-object-profile.ts`; `--check` verifies. Reference implementation: `sdk/src/profiles/object.ts`, portable, reachable as `object` from both preview entries.

## Not in scope

Other components of an object (each is its own kind, naming the object as `subject`), relationships between objects (`assign`, a later kind), containment (a later logistics kind), and any claim that an object physically exists.
